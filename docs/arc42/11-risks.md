# 11. Risks and Technical Debt

Observed in the code during the initial documentation pass (2026-10-02). These are **findings, not
decisions** — each needs a call from the project owner (fix, accept, or turn into a story).

| # | Type | Finding | Where | Impact |
|---|---|---|---|---|
| R-1 | Debt / possible bug | Nothing ever sets a Shipping to `DONE`, so a ship that has been Released can never get a new Shipping. | `Ship.createNewShipping`, `ShippingState` | Resolved by STORY-007: the Origin Harbor sets the Shipping to `DONE` when it consumes `ship-arrived` (6.4). |
| R-2 | Possible bug | The Sailors Code is `mod 14` (0–13) but 15 Shipping Quotes (0–14) are seeded; the last quote is unreachable. | `SailorsCode`, `V4__quotes.sql` | Minor; one quote never shown. |
| R-3 | Debt | A rejected cargo load (too heavy) returns `200` with the unchanged ship; other rule violations surface as `500`. | `CargoLoadManagementService`, controllers | Client cannot tell success from rejection; see 8.4. |
| R-4 | Risk | Kafka and Debezium are not part of the Kubernetes deployment; Releases on the cluster are written to the outbox but never published. | `k8s/`, ch. 7 | The outbox table grows; the terminal sees nothing on k8s. Once Harbors exchange ships (ADR-0004), voyages cannot work on k8s at all. |
| R-5 | Risk | Credentials are in plain text in `application.yml`, the Compose files and the connector JSON; `k8s/10-secrets.yaml` (base64) is committed. | config files | Acceptable only for a playground; must not be reused elsewhere. |
| R-6 | Debt | A second Debezium connector streams the `catains` table to Kafka with no consumer. | `kafka-connect/connectors/catain-connector_*.json` | Unused infrastructure, unclear intent. |
| R-7 | Risk | Tests run per component, and the Postgres tests only under `-Pdb` ([ADR-0010](../adr/0010-test-each-component-in-isolation.md)). | 8.8, `ship-backend` | SQL, migration and transaction mistakes surface in CI, not in the local build. Kafka behaviour, the outbox → Debezium → topic path and cross-component flows are verified only by hand on the Compose stack. |
| R-8 | Risk | `ship-terminal` duplicates the event classes instead of sharing a schema. | `ship-terminal/Main.kt` | Event changes can silently break the consumer (unknown fields are ignored, removed ones are not). EPIC-003 adds fields to `shipping-published` (quantities, Home Harbor, Earnings) and [ADR-0009](../adr/0009-carry-crew-with-the-ship-and-fill-recruit-pools-per-harbor.md) adds the Crew: keep them additive ([ADR-0008](../adr/0008-carry-earnings-home-with-the-ship.md)). |
| R-9 | Debt | Images are deployed as `:latest`; the frontend image is not built by CI. | ch. 7.3 | Deployments are not reproducible. |
| R-10 | Risk (resolved, residual) | A return Arrival processed before the earlier `ship-arrived` for the same ship (a round trip through three or more Harbors when one Harbor's connector lags, or a repartitioned `hexagonship-shipping`). | `ArrivalManagementService`, `arrivals` (`V11__arrivals.sql`) | Resolved by STORY-007 review: re-publications are dropped by the Shipping id in `arrivals`, not by fleet membership, and a returning ship still at sea from this Harbor ends that voyage implicitly and stays in the fleet; the late `ship-arrived` is a no-op (6.4). Residual: Arrivals handled before V11 are not in `arrivals`, so a re-publication of such a Release while the ship is at sea from that Harbor again would end its current voyage and take it back in. A Refused Delivery (decided, [ADR-0007](../adr/0007-unload-incoming-ships-manually-after-arrival.md)) is a return voyage no User Released and follows the same rules. |
| R-11 | Risk | The fleet-events registry (open SSE streams) is in memory per backend instance. With several replicas of one Harbor, a tab only sees the fleet changes its own replica handled. | `FleetEventEmitters`, `k8s/30-backend.yaml` (2 replicas), [ADR-0006](../adr/0006-push-fleet-changes-to-the-frontend-with-server-sent-events.md) | No effect today: k8s has no Kafka (R-4), so no replica handles Arrivals. If Kafka lands on k8s, fleet changes need a broadcast across replicas (for example each replica consuming in its own group), or a reload shows them. |
| R-12 | Open question (resolved) | A ship refused by its own Home Harbor has nowhere left to sail. | [ADR-0007](../adr/0007-unload-incoming-ships-manually-after-arrival.md), STORY-028 | Resolved 2026-10-07 by STORY-028: the ship stays in its Home Harbor's fleet with its Cargo aboard, nothing is paid, and the refused Cargo cannot be unloaded into that Stock while preparing, only delivered to another Harbor (6.7). |
| R-13 | Risk | Earnings ride with the ship: a ship that never reaches its Home Harbor, or sails to a Harbor that never answers, keeps them out of every Savings. | [ADR-0008](../adr/0008-carry-earnings-home-with-the-ship.md) | Accepted as part of the game; money is never duplicated, only delayed or stranded. |
| R-14 | Debt | Weight is a binary float while money is an exact decimal (ADR-0008). | `Cargo.weight`, `Ship.currentWeight` | Two numeric conventions in one model; Weight sums can drift in the last digit. |
| R-15 | Debt | Catain Images are not in the repository: Compose and k8s only create the bucket, the images were uploaded by hand, and Catain Purrbossa's image id points at no image. | `V3__catains.sql`, `k8s/21-minio.yaml` | A new Harbor shows no Catain Images; STORY-017 fixes it. |
| R-16 | Risk | The Crew rides with the ship and Recruit Pools differ per Harbor: a lost or stranded ship takes its Crew with it, every Harbor keeps copies of foreign Crew Members, and `shipping-published` grows with the Crew. | [ADR-0009](../adr/0009-carry-crew-with-the-ship-and-fill-recruit-pools-per-harbor.md) | Accepted as part of the game, like R-13. Recruit images, if any, have no shared source (cf. R-15). |
